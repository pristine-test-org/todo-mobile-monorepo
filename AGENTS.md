# Tally

- npm workspaces monorepo with three apps under `apps/`: `web` and `admin` are Vite + React 19 +
  TypeScript single-page apps; `mobile` is an Expo (React Native) app for iOS and Android only.
  One `package-lock.json` at the root; run `npm install` there, never inside an app.
- Every app shares one React version (the one the Expo SDK pins). Bump React in all three
  `package.json` files together, and bump Expo packages with `npx expo install` from `apps/mobile`.
- All three apps read and write the same Supabase `todos` table directly through supabase-js; each
  app's client is in `apps/<app>/src/lib/supabase.ts`. There is no server. The mobile client follows
  Supabase's React Native setup (URL polyfill, AsyncStorage for the session).
- The schema is in `supabase/migrations/` at the root and is shared. Schema changes go in a new
  migration file and must work for all three apps.
- Each app has its own look, described in its `DESIGN.md`: plain CSS in `src/index.css` for the web
  apps, `StyleSheet` with the tokens in `src/theme.ts` for mobile. Don't share styles between apps
  and don't add a UI library.
- The mobile app has no web target: no `react-native-web`, no `web` script, `platforms` stays
  `["ios", "android"]`. `ios/` and `android/` are generated by `npx expo prebuild` and not committed.
- `web` and `admin` are each a Vercel project whose root directory is the app's folder. The mobile
  app is not deployed from this repo.
- Checks at the root: `npm run build` and `npm run lint` (web apps), `npm run typecheck` (all
  three). For mobile also run `npx expo-doctor` in `apps/mobile`.
